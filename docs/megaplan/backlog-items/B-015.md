# B-015: Reaction Tracker

**Objective:** Store Discord reactions on briefing embeds in SQLite and wire up an event listener.

**Status:** done

**Notes:**
- `src/resenha/reactions.py` created: SQLite-backed ReactionTracker with track(), get_stats(), get_source_stats().
- `src/resenha/listener.py` created: ReactionListener with emoji mapping and Discord event hook.
- `src/resenha/pipeline.py` updated: captures message IDs from run_bot(), saves briefing registry JSON.
- `src/resenha/delivery.py` updated: send_briefing() and run_bot() return message IDs.
- `tests/test_reactions.py` created: 7 tests.
- `tests/test_listener.py` created: 8 tests.
- All 76 tests pass.

**Tasks:**
1. Create `src/resenha/reactions.py`:
   - `ReactionTracker` class wrapping a SQLite table `reactions`.
   - Schema: `id INTEGER PK AUTOINCREMENT, briefing_run_id TEXT, message_id INTEGER, embed_index INTEGER, asset_ticker TEXT, reaction TEXT, user_id INTEGER, created_at TEXT DEFAULT (datetime('now'))`.
   - `track(briefing_run_id, message_id, embed_index, asset_ticker, reaction, user_id)` — INSERT.
   - `get_stats(days=7)` — SELECT counts grouped by asset_ticker and reaction, for the last N days.
   - `get_source_stats(days=7)` — SELECT counts grouped by source (from asset_ticker mapping), for the last N days.
   - Uses the same `data/resenha.db` path, separate table. Auto-creates table on init.
2. Create `src/resenha/listener.py`:
   - `ReactionListener` class that wraps `discord.Client` with `on_reaction_add` event.
   - On reaction: extracts `message_id`, `user_id`, `emoji` (as string).
   - Maps emoji to reaction label: `👍` → "up", `👎` → "down", `❤️` → "love", `🔥` → "fire". Unknown emoji → skipped.
   - Determines `asset_ticker` by looking up the message from a `briefing_registry` dict (briefing_run_id → list of (message_id, embed_index, ticker)).
   - Calls `ReactionTracker.track()`.
3. Update `src/resenha/pipeline.py`:
   - After `run_bot()` sends embeds, collect Discord message IDs and populate a `briefing_registry`.
   - Store the registry in a simple JSON file `data/briefing_registry.json` keyed by `briefing_run_id`.
4. Write tests in `tests/test_reactions.py`:
   - Test schema creation: table exists with correct columns.
   - Test `track()` inserts a row.
   - Test `get_stats()` returns correct counts grouped by ticker and reaction.
5. Write tests in `tests/test_listener.py`:
   - Test emoji mapping: `👍` → "up", `👎` → "down", unknown → skipped.
   - Test `on_reaction_add` calls `track()` with correct params (mock ReactionTracker).

**Acceptance Criteria:**
- `reactions` table created in `data/resenha.db` on first use.
- `track()` persists reaction events.
- `get_stats()` returns aggregated counts.
- Listener maps standard emojis correctly and ignores unknown ones.
- All existing + new tests pass.
