# B-030: Tratamento operacional de erros do Gemini

**Objective:** Classificar falhas do Gemini, repetir apenas erros transitórios e informar falhas relevantes no Discord sem expor dados sensíveis.

**Status:** PENDING

## WHAT — Qual é o problema?

Algumas falhas do Gemini podem interromper o pipeline sem gerar um aviso operacional no Discord. Além disso, o cliente atual trata explicitamente apenas HTTP 429 para retry.

## WHY — Por que ele existe?

Falhas transitórias podem ser recuperadas com novas tentativas, enquanto falhas permanentes não devem ser repetidas. Sem uma política explícita, o sistema pode desistir cedo demais, repetir erros sem utilidade ou deixar o operador sem informação.

## HOW — Como solucionar?

### Erros transitórios

Repetir automaticamente, com limite e backoff:

- HTTP 429.
- HTTP 500, 502, 503 e 504.
- Timeout, conexão interrompida e falhas temporárias de rede.

Após esgotar as tentativas, tratar como erro operacional.

### Erros permanentes

Não repetir automaticamente:

- HTTP 400.
- HTTP 401 e 403.
- Modelo inexistente ou indisponível.
- Prompt ou resposta fora dos limites permitidos.

Registrar a causa e interromper a geração.

### Comunicação operacional

Enviar uma mensagem operacional ao Discord quando houver:

- retries esgotados;
- erro permanente de autenticação ou configuração;
- resposta vazia ou inválida;
- impossibilidade de gerar o briefing.

A mensagem deve conter horário, etapa, classificação, código HTTP quando houver e orientação de correção. Não deve conter chave, token, prompt completo, carteira, emails ou dados pessoais.

## Acceptance Criteria

- Cada categoria de erro possui tratamento definido e testado.
- Retries têm limite e backoff.
- Erros permanentes não são repetidos inutilmente.
- Falhas relevantes geram mensagem operacional no Discord.
- Mensagens operacionais não expõem dados sensíveis.
- A suíte existente continua passando.

## Non-goals

- Alterar o modelo Gemini.
- Alterar o conteúdo ou o estilo dos briefings.
- Alterar a política de fallback das fontes de dados.
- Implementar circuit breaker ou observabilidade externa.
