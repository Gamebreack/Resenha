# B-025: Fix mypy type errors

**Objective:** Eliminate all `mypy src/` errors and prevent regressions by adding a type-check gate.

**Status:** done

**Background:**
- Current baseline: 22 errors across 12 files.
- New errors were introduced by B-024's `agenda.py` (missing stubs for `googleapiclient.discovery`).
- Remaining errors are pre-existing type issues in `cache.py`, `prices.py`, `news.py`, `listener.py`, `delivery.py`, `portfolio.py`, `gemini.py`, `summary.py`, `bias.py`, `scheduler.py`, and `__main__.py`.

**Tasks:**
1. Run `mypy src/` and record the full list of errors.
2. Fix errors using the least invasive approach:
   - For missing third-party stubs (`yfinance`, `feedparser`, `googleapiclient.discovery`), add `# type: ignore[import-untyped]` comments.
   - For `Returning Any` errors, add explicit return annotations/casts where the actual runtime type is known.
   - For real type bugs (e.g., incompatible assignment, missing return, missing named arguments), fix the code.
3. Add a `mypy` check to the project's quality gate:
   - Add a `[tool.mypy]` section to `pyproject.toml` with `strict = false`, `ignore_missing_imports = false`, and `warn_return_any = true`.
   - Or add a `mypy src/` invocation to the existing test command documentation. Prefer config in `pyproject.toml`.
4. Update README or CONTRIBUTING to mention running `mypy src/` before committing.
5. Ensure `python -m pytest tests/ -q` still passes after changes.
6. Ensure `mypy src/` reports zero errors.

**Acceptance Criteria:**
- `mypy src/` exits 0 with no errors.
- All pytest tests pass.
- No runtime behavior changes except where required to fix genuine type bugs.
