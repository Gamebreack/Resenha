# B-028: Tornar o scheduler consciente de timezone e misfires

**Objective:** Garantir que os horários do Resenha sejam interpretados no fuso local correto e definir o comportamento quando uma execução agendada for perdida.

**Status:** PENDING

**Context:**
- O scheduler atual usa um offset fixo para BRT.
- O horário esperado do usuário é 19:00 em `America/Sao_Paulo`.
- Uma indisponibilidade do processo pode fazer uma execução ser perdida sem política explícita.

**Tasks:**
1. Substituir offsets fixos por `zoneinfo.ZoneInfo("America/Sao_Paulo")`.
2. Definir e documentar a política de misfire: executar, pular ou alertar.
3. Garantir que a política não duplique briefings já concluídos.
4. Adicionar testes para conversão de horário e execução perdida.
5. Atualizar README e documentação operacional com o timezone oficial.

**Acceptance Criteria:**
- O horário configurado é interpretado explicitamente em `America/Sao_Paulo`.
- A política de misfire está documentada e testada.
- Não há duplicação quando uma execução é retomada.
- A suíte existente continua passando.

**Non-goals:**
- Alterar o horário desejado dos briefings.
- Alterar o conteúdo do briefing.
- Alterar o cliente Gemini.
