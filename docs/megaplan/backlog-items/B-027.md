# B-027: Proteção de persistência local contra concorrência

**Objective:** Tornar as escritas no SQLite e no registro JSON do briefing seguras contra execuções concorrentes e interrupções durante a persistência.

**Status:** PENDING

**Context:**
- O pipeline pode ser executado manualmente e pelo scheduler.
- O registro `data/briefing_registry.json` é compartilhado com o listener de reações.
- A implementação atual não documenta lock de processo nem escrita atômica do JSON.

**Tasks:**
1. Definir a política de concorrência esperada para pipeline, listener e cache.
2. Implementar lifecycle explícito para conexões SQLite.
3. Adicionar lock apropriado para operações concorrentes.
4. Tornar a atualização do registro JSON atômica, usando arquivo temporário e rename.
5. Tratar JSON inválido e interrupções sem perder o registro anterior.
6. Adicionar testes para duas operações concorrentes e falha durante escrita.
7. Atualizar a documentação operacional.

**Acceptance Criteria:**
- Execuções concorrentes não corrompem o SQLite nem o registro JSON.
- Uma falha durante a escrita preserva a última versão válida do registro.
- O comportamento de lock e retry está documentado.
- Testes automatizados cobrem concorrência e interrupção.
- Toda a suíte existente continua passando.

**Non-goals:**
- Alterar o conteúdo dos briefings.
- Alterar a política de fallback das fontes.
- Alterar o scheduler ou o cliente Gemini.
